# expo-demo

The only deployable target — a composition root, not a place for product code. It mounts features into Expo Router
routes and owns the native/build configuration.

## Map

| Path | What it is |
| --- | --- |
| `app/_layout.tsx` | Root: enables immer Map/Set, screens freeze, then `Providers` + a `Stack` gated on `useUserStore.use.onboarding()`, plus `<SplashScreen />`. |
| `app/(public)/` | Pre-onboarding route group. `index.tsx` re-exports `Onboarding`. |
| `app/(protected)/` | Post-onboarding group; its layout paints the stack background from the theme. |
| `app/(protected)/(tabs)/` | Kara's native `Tabs` (from `~/core.ui`) with `index` → `feature-home`. |
| `app.config.ts` | Per-`EXPO_PUBLIC_STAGE` (development/preview/production) app name, scheme, icons, splash; Kara's plugin for the SVG icons in `core-resources`, nitro-fetch's plugin, and the four `core-expo-plugins` that link the native secure-core libraries. |
| `assets/{stage}/` | App icon and splash images per stage — `app.config.ts` picks the folder by `EXPO_PUBLIC_STAGE`. |
| `eas.json` | EAS build profiles matching those stages. |
| `metro.config.js`, `babel.config.js` | Monorepo-aware bundler config. Reanimated's worklets plugin is injected by `babel-preset-expo`. |
| `ios/`, `android/` | Generated by prebuild. Not hand-edited — change `app.config.ts` or a plugin instead. |

## Rules

**Route files are one-line re-exports.** All screen logic lives in a `feature-*` package. Never add `.ios.tsx` /
`.android.tsx` route files — Expo Router would register them as separate routes.

**Native config changes need a rebuild.** Touching `app.config.ts`, a plugin, an icon, a package with native code or
anything in `packages/platform-secure-core` means `yarn ios:dev` / `yarn android:dev` (clean prebuild), not a Metro
reload. The secure-core plugins are not idempotent, which is why every script prebuilds from clean.

**A tab needs an icon from `core-resources/icons`.** `Tabs.Screen` takes `icon` (and `selectedIcon`) by name, typed
from `types/native-icons.d.ts`; there are no SF Symbols or icon fonts.

`EXPO_PUBLIC_STAGE` drives everything environment-shaped — `app.config.ts` picks the assets, scheme and name from it,
and `core-config` validates the same variable at runtime. It comes from the scripts and the `eas.json` build profiles;
no env file is committed, and `.env*` is ignored. Running `expo` directly, without a stage, falls back to `production`
for the config and throws at startup by design.
