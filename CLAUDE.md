# react-native-expo-monorepo

Turborepo + Yarn 4 workspaces. An Expo app whose UI is **Kara** (`@hzblj/kara-ui`): real SwiftUI and Jetpack Compose
views through `@expo/ui`, styled by one token-typed `sx` engine.

Every package has its own `CLAUDE.md` — read that one before touching the package.

## Map

| Path | What lives there |
| --- | --- |
| `apps/expo-demo/` | The only deployable target. Expo Router routes, `app.config.ts`, native projects. Routes are one-line re-exports of features. |
| `packages/core-ui/` | The UI domain: Kara re-exported, plus the app's own components built from Kara's primitives. |
| `packages/core-*/` | The rest of the platform-agnostic foundation: store, i18n, hooks, config, services, resources. |
| `packages/feature-*/` | One product capability each: `home`, `onboarding`, `splash-screen`, `providers`. |
| `packages/platform-secure-core/` | Native-only Swift/Kotlin libraries (no JS) that supply the storage + encryption keys. |
| `packages/expo-storage/` | Local Expo native module bridging `platform-secure-core` to JS. |
| `packages/core-expo-plugins/` | Expo config plugins (TypeScript) that graft the native libraries into the generated iOS/Android projects. |
| `types/globals.d.ts` | Ambient globals (`__DEV__`, `process.env`). Pulled in once as `files` in the root tsconfig. |
| `types/native-icons.d.ts` | The app's icon names, generated by Kara's config plugin from `packages/core-resources/icons`. Committed, so `yarn typecheck` works on a fresh clone. |

Dependency direction is strict and one-way: `app → feature-* → core-*`. `core-*` never imports a feature; features
never import each other.

## Commands

```bash
yarn ios / yarn android      # run the demo app
yarn ios:dev                 # clean prebuild + run (needed after native/plugin/icon changes)
yarn typecheck               # turbo: tsc per package
yarn lint                    # turbo: biome + tsc
yarn biome:fix               # apply safe lint/format fixes
yarn doctor                  # expo-doctor
```

## Conventions that bite

**Kara is reached through `~/core.ui`, never imported directly.** `core-ui` re-exports `@hzblj/kara-ui` and
`@hzblj/kara-ui/router`; Biome's `noRestrictedImports` rejects both (and `@expo/ui`) outside `packages/core-ui`. A
component of the app's own goes into `core-ui` and is exported from there, so features keep one import path whatever
the component's origin.

**Imports use aliases, never relative paths across packages.** `~/core.ui`, `~/core.hooks`, `~/core.i18n`,
`~/core.store`, `~/core.config`, `~/core.services`; the rest resolve through `~/*` → `packages/*` (`~/feature-home`).
Import from a package's entry point only — no deep imports past `index.ts`.

**`app/` holds no logic.** A route file re-exports a finished feature (`export default Home`). Never create
`.ios`/`.android` route files.

**Style through `sx` props, never raw values.** `p="s16"`, `bg="surface.primary"`, `borderRadius="large"` — a raw
number or hex does not type-check. Layout keys also take `{base, sm, md, lg, xl}`.

**Native views need a host.** Kara's `@expo/ui`-backed atoms (`Text`, `VStack`, `Button`, …) only render inside
`<Screen>` or `<Island>`; outside one they silently disappear (dev warns via `useHostGuard`). `Box` and the `Rn*`
components are the React Native tier and need none.

**Icons are SVGs, not a font.** Drop one into `packages/core-resources/icons` (paths only, no groups, masks or
strokes), then run a clean prebuild: the plugin makes it a native asset on both platforms and adds its name to
`types/native-icons.d.ts`.

**Network calls go through `Fetcher` in `~/core.services`** (nitro-fetch), not the global `fetch` and not
`react-native-nitro-fetch` directly.

**Yarn quarantines new versions for 24 hours.** `@hzblj/*` is pre-approved in `.yarnrc.yml`, so a Kara release can
land at once; anything else that is too fresh fails resolution with `YN0016` — lower the range's floor instead of
pre-approving it.

**Kara pins the Expo SDK.** Its peers require `expo ~57.0.0`; an SDK upgrade waits for a Kara release that supports it.

Code style is Biome-enforced: 2 spaces, 120 cols, single quotes, no semicolons, sorted imports and object keys. Named
exports and `const` arrow functions everywhere; `type` over `interface`.
